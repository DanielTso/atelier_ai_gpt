### Source Layout

- `src/app/page.tsx` — Single-page client; all application state lives here
- `src/app/actions.ts` — Server actions for all DB reads/writes
- `src/app/api/` — API routes (chat, models, embed, summarize, documents, etc.)
- `src/components/chat/sidebar/` — Decomposed sidebar: `Sidebar.tsx` (orchestrator — renders `SidebarHeader`, `SidebarNav`, `RecentsSection`, `SidebarFooter`, `CollapsedSidebar`), `types.ts` + `SidebarActionsContext.tsx` (shared types/context), `ChatItem`, `SmartChatMenu`. (The pre-decomposition section components `QuickChatsSection`/`ProjectsSection`/`ArchivedSection`/`ProjectItem` + `useCollapseState` were dead and removed in v4.51.0.)
- `src/components/chat/` — Other chat components (MessagesList, ChatInputArea, ChatContextMenu, ProjectLandingPage, etc.)
- `src/components/chat/DocumentCard.tsx` — Shared thumbnail card for document grids: shows first-page WebP thumbnail (signed `thumbnailUrl`) with a file-type-tile fallback for text/code/docx; filename; status icon (spinners for `uploading`/`processing`, check for `ready`, alert for `error`); a `vision` chip when `extractionMethod === 'vision'`; chunk count; hover-to-reveal delete; click opens preview. Used in both `ProjectDocumentsDialog` and `ProjectLandingPage`.
- `src/components/chat/ArtifactCard.tsx` — Card for Claude-generated file artifacts: icon by type (xlsx/docx/pdf), title, type label, and a direct Download link using the signed `downloadUrl`. Rendered by `MessagesList` below assistant messages that produced artifacts.
- `src/components/ui/` — Reusable UI (dialogs, selectors, command palette)
- `src/components/ui/DocumentPreviewDialog.tsx` — Tabbed document preview: "Preview" tab shows the original file inline (images directly; PDFs in an `<iframe>` via the signed `url`; docx/text show text only) + "Extracted text" tab (existing chunk reconstruction). An "Open original" link is always available.
- `src/components/settings/` — Settings tab components
- `src/hooks/` — Custom hooks (useLocalStorage, usePersonas, useAppearanceSettings, etc.). **`useDialogs`** (the 10 dialog flags + 6 targets behind a per-dialog controller) and **`useChatPersistence`** (the turn pipeline — at turn start: user attachments + user embed; at turn end: generated-image linking, embed, persona usage, summarize, auto-memory, title, artifact re-fetch; every id comes from the turn metadata `/api/chat` sends, and it writes no message text; unit-tested) were extracted from `page.tsx` in v4.33.0; **`useChatSessions`** holds one AI SDK `Chat` instance per DB chat (the active one feeds `useChat({ chat })`), binds each request's `chatId` to the session it is sent through, and reports every turn's start and finish with the chat it was sent from — see "Chat turns" in [data-flow.md](data-flow.md); **`useWebIngest`** drives "Add from web" (map + per-page ingest); **`useUrlNavSync`** (v4.49.0) mirrors nav state (`activeView`/`activeProjectId`/`activeChatId`) into the URL via the native History API — browser back/forward walk in-app views, deep links/refresh restore; the URL scheme lives in `src/lib/navState.ts` (pure `parseNavUrl`/`navToUrl`: `?view=`, `?project=`, `?chat=`); `useSearchParams` is deliberately avoided (it would force a Suspense boundary around the single-page app). A popstate re-seeds the hook's dedupe baseline with the popped URL (no "applying a pop" flag, which a no-op pop used to leave armed), and a URL change that only resolves or moves the SAME chat's project segment is a `replaceState`, never a push. Stale deep links are judged in `page.tsx` only after all three chat lists (project, quick, archived) have loaded — see `chatLookup.ts`. Dialogs/artifact panel/lightboxes are intentionally NOT in history.
- `src/hooks/useDocumentUpload.ts` — Shared 3-step upload hook (request upload-url → `uploadToSignedUrl` → process). Used by both `ProjectDocumentsDialog` and `ProjectLandingPage`; fixes a regression where the landing page was still POSTing to the retired inline `/api/documents` endpoint.
- `src/lib/` — Utilities: `settings.ts` (DB-first/env-fallback config), `embeddings.ts` (pgvector search), `retrieval.ts` (RAG pipeline orchestrator, incl. hybrid RRF fusion), `ragConfig.ts` (tunable RAG knobs), `queryRewrite.ts` (conversational query rewrite), `rerank.ts` (LLM rerank), `mmr.ts` (diversity selection), `chunking.ts` (document chunker), `keywordSearch.ts` (RAG Phase 3 — `findChunksByKeyword`: Postgres FTS over `content_tsv` + trigram `ILIKE` on identifier tokens like `SW-101`; `identifierTokens`), `rrf.ts` (RAG Phase 3 — `rrfFuse`: Reciprocal Rank Fusion merging ranked candidate lists by `1/(k+rank+1)`), `chatStage.ts` (pure stage machine driving `ThinkingStatus` copy from stream parts — `reading-documents` maps an active `read_document` tool part), `chatTurn.ts` (the chat-turn persistence contract shared by `/api/chat` and the client: `TurnMetadata` + `readTurnMetadata`, `isDbMessageId`, and `createAssistantTurnRecorder` — the stream transform that saves the assistant row exactly once), `fileAttachments.ts` (image/file handling), `providers.ts` (shared AI provider factory), `fileExtraction.ts` (shared file parsing), `errors.ts` (API error helper), `validation.ts` (Zod request schemas), `storage.ts` (server-only Supabase Storage wrapper — `isStorageConfigured`, `createSignedUploadUrl`, `uploadBuffer`, `downloadToBuffer`, `createSignedDownloadUrl`, **`createSignedDownloadUrls`/`signedArtifactUrls`** (batch — one `createSignedUrls` request signs many vs N round-trips; HTML split for download-disposition; used by `getAllArtifacts`/`getGeneratedImages`/`getChatAttachments`/documents route), `removeObjects`; uses service-role key), `thumbnails.ts` (`generatePdfThumbnail` + `generateImageThumbnail` → WebP via `@napi-rs/canvas`, best-effort), `storageClient.ts` (browser-side anon-key Supabase client for `uploadToSignedUrl`), `tavily.ts` (server-only Tavily `mapSite`/`extractUrl` wrapper — web ingestion, key via `getTavilyApiKey`), `ingest.ts` (shared `ingestText` tail: chunk→save→embed→status, used by both `documents/process` and `documents/web-ingest`), `utils.ts` (incl. `formatPageList` — run-length page-range formatting for the Partial badge tooltip), `navState.ts` (v4.49.0 — pure URL⇄NavState mapping for browser-history sync; consumed by `useUrlNavSync`), `chatLookup.ts` (pure rules over page state's three chat lists: `findChatById` (project → quick → archived), `isStaleChatId` (stale only once all three lists have loaded), `moveRestoredChat`, `removeProjectChats`), `highlighter.ts` (v4.50.0 — lazy client-side shiki v4 singleton, `codeToHtmlSafe`/`resolveShikiLang`, dual vitesse themes, grammars loaded on demand; used by chat `CodeBlock` + code `ArtifactPreview`)
- `src/lib/documents/` — RAG Phase 3 whole-document mode: `tool.ts` (`createReadDocumentTool` — the AI SDK v6 `tool()` for `read_document`; reads a project document's stored `extracted.txt` from Storage window-by-window, project-scoped, in-band errors on missing text, surfaces `unavailablePages` from `failed_pages`) and `windowing.ts` (`sliceWindow` — cuts on `# Page n` anchors when present, falls back to character-offset windows; capped at `READ_DOC_WINDOW_CHARS`, default `100000` chars ≈ 25k tokens).
- `src/lib/artifacts/` — Artifact engine: `types.ts` (`ArtifactType` = `xlsx|docx|pdf|pptx|html|code`, `SheetSpec`, `RenderedArtifact` — `ext` is a string: the type itself for documents, the language extension for code); `code.ts` (v4.50.0 — `CODE_LANGUAGES` registry: id/label/ext/shikiLang for python·bash·typescript·javascript·sql·json·yaml·markdown·powershell; a code artifact's LANGUAGE persists in the `format` column, `type='code'` `format='python'` — no migration); `style.ts` (Atelier brand palette + per-library color/font helpers); `markdown.ts` (`parseMarkdown` → neutral AST via the `marked` lexer, plus `mdToPlainText`); `toXlsx.ts`/`toDocx.ts`/`toPdf.ts`/`toPptx.ts` (brand-styled renderers — styled headers, real tables, lists, page numbers; xlsx cells run through `mdToPlainText` so raw Markdown never leaks); HTML and code need no renderer (the model's string IS the file — `text/html` / `text/plain`); `render.ts` (`renderArtifact(type, title, content, language?)` dispatch); `tool.ts` — the AI SDK v6 `tool()` for `generate_artifact`. Claude calls it with `{ type, title, format, content, language? }` (`format` = `markdown|sheets|html|code`; `language` required for code); `execute` renders the file, uploads to `artifacts/<projectId|standalone>/<id>/<slug>.<ext>`, persists an `artifacts` row (+ seeds version 1), and returns `{ artifactId, title, type, downloadUrl }` (signed URL TTL `ARTIFACT_URL_TTL_SECONDS` = 24h). The tool is **chat-first**: only generate a file on an explicit file/web-page request, otherwise answer in chat. Wired into `/api/chat` for Claude when a `chatId` exists and Storage is configured.
- `src/lib/image/generate.ts` — shared `generateImageBytes(prompt, aspectRatio?) → { bytes, mediaType, ext }` (Nano Banana 2 `gemini-3.1-flash-image` via `generateText` + `responseModalities`; key-guarded with specific error messages). Used by BOTH the chat `generate_image` tool and the standalone `POST /api/images/generate` route (DRY).
- `src/lib/download.ts` — `downloadFile(url, filename)` blob-fetches a (cross-origin) URL and saves it on-page (the HTML `download` attr is ignored cross-origin), tab-fallback on CORS; `imageExt(mediaType)`. `src/components/ui/Lightbox.tsx` — shared portal-based (to `document.body`) image lightbox used by the Images gallery + chat (escapes ancestor stacking/overflow contexts).
- `src/lib/image/tool.ts` — the AI SDK v6 `tool()` for `generate_image`: Claude generates an image **inline** via Nano Banana 2 using `generateImageBytes`, uploads it to storage, and returns a small descriptor `{ storagePath, url, mediaType, filename, fileSize }` (no base64 in the conversation). The turn pipeline (`useChatPersistence`, at turn end) links it to the assistant message — the row `/api/chat` saved, id from the turn metadata — via `saveGeneratedImage` and renders it inline. Merged into the Claude tool set alongside `generate_artifact` (see `TOOL_GUIDANCE` in `/api/chat`).
- `src/types.ts` — Shared TypeScript interfaces (`Model`, `DocumentStatus`, `DocumentSummary`). `DocumentSummary` is the canonical document shape used across `ProjectDocumentsDialog`, `ProjectLandingPage`, and `DocumentCard`, replacing three former local `Document` interface duplicates.
- `src/db/` — `schema.ts` (Drizzle schema), `index.ts` (postgres-js pool; `prepare: false` for the Supabase transaction pooler)
