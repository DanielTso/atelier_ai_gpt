# Chatlog — 2026-06-17 — Phase C3: documents UI

## Goal

Surface what C-storage produces in the UI: thumbnail cards for every document surface, a tabbed preview dialog, an extraction-method badge, and a shared upload hook that also fixes a broken uploader regression.

## Brainstorm decisions

- **Thumbnail card (option A: dedicated `DocumentCard` component).** Shared across both surfaces — avoids duplicating the thumbnail/status/badge/delete logic in `ProjectDocumentsDialog` and `ProjectLandingPage`.
- **Tabbed preview (option A).** "Preview" tab renders the original file inline (image or PDF iframe); "Extracted text" tab keeps the existing chunk reconstruction. Docx/text show text-only (no meaningful inline preview). An "Open original" link is always available.
- **Vision/text method badge: in.** Cheap signal for users to know whether Gemini vision was needed. Displayed as a small chip on `DocumentCard`.
- **Uploader fix: must-have.** `ProjectLandingPage` was still calling the retired inline `/api/documents` endpoint — broken since C-storage Stage 1 landed. The shared `useDocumentUpload` hook fixes it as a byproduct of the refactor.
- **Image uploads: in** for both surfaces (png/jpg/jpeg/webp) — C2 already handles extraction; just needed to widen the accept filter and MIME guard.
- **`DocumentSummary` type: consolidate.** Three local `Document` interfaces (one in each consumer file) replaced by a single exported type in `src/types.ts`.
